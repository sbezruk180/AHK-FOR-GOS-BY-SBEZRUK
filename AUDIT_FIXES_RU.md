# Исправления технического аудита

Основа изменений — приложенный основной AHK и совпадающие с репозиторием UDF/common/helper. Текст аудита использован как перечень дефектов. Код сохраняет CP1251, CRLF и требование AutoHotkey 1.1.37.02 ANSI x86.

## Дополнения

- **OBS:** переключатель «Скрыть окна из захвата OBS» на странице «Интерфейс» сохраняется вместе с настройками; исправлен пропуск его значения при сохранении. Используется `WDA_EXCLUDEFROMCAPTURE` для окон этого процесса, с проверкой результата. Требуется Windows 10 2004+ или Windows 11. Совместимость зависит от способа захвата OBS; скрытие игры эта настройка не выполняет. Проверка выполняется до показа окна и затем для всех собственных окон. Ошибки повторяются через 2 секунды; статус показывает число окон с подтверждённым флагом и код отказа. Для проверки используйте в OBS «Захват окна» с методом Windows 10 (1903 и новее) и сделайте короткую запись. BitBlt и сторонние способы захвата могут игнорировать флаг.
- **Поиск:** точные ссылки на статьи, словоформы, исправление ограниченных опечаток по словарю корпуса, более высокий вес заголовка статьи, точный проход перед приблизительным. Поддерживаются `"точная фраза"` и `-исключение`. SHA-256 содержимого входит в поколение индекса; добавленный или изменённый документ обновляет индекс и кэш запросов. Недоступные документы перечисляются явно.
- **Auto ID:** сохранён рабочий источник из присланной версии: `B6F3B8 + 0x79C`, резерв `B6F5F0`. Пассивный бинд ПКМ запускает поиск после обработки нажатия игрой, с начальным ожиданием 20 мс и опросом 20 мс во время прицеливания. После захвата, отпускания ПКМ или потери фокуса таймер останавливается. Убраны повторные паузы 12 мс и выделения массивов для каждого игрока. Точный ID принимается при первом наблюдении с независимой проверкой прицела, связи PED/слота, процесса и поколения отмены; маски сохраняют 3 наблюдения. Полный поиск охватывает и ID 1003, проверяет дубликаты. 20 мс — интервал запуска, а не обещание времени полного захвата. Чтение отделено от удалённой записи: отсутствие необязательного эталонного хеша больше не блокирует Auto ID и чтение состояния чата, но структура x86-модуля, диапазоны и связи объектов проверяются. Явно заданный неверный хеш по-прежнему запрещает доступ.
- **GUI:** карточки персонажа, патруля и поста; ровная сетка полей; сведения об активном профиле; единая палитра с проверкой контраста; доступные с клавиатуры кнопки вместо текстовых псевдокнопок; ограничение окна рабочей областью монитора и прокрутка на небольших экранах. Подписи и поля масштабируются вместе при повышенном DPI; обычный текст явно сбрасывает жирный шрифт. Увеличены интервалы в профиле, разделены блоки настройки цветов/OBS/таймера, длинные страницы получают собственную высоту и нижнюю строку за последним полем. В HUD устранены пересечения подписи с заголовком и значениями; текст результатов поиска и LAW имеет прокрутку.

## Печать чата и временный ввод ID

На странице «Чат и безопасность» добавлены русские подписи режимов «Авто», «Память», «Вставка», «Печать всего» и «Печать фракции». INI сохраняет соответствующие внутренние значения `Auto`, `Memory`, `Keyboard`, `FastTyping`, `FactionTyping`, сохраняя чтение ранее записанных режимов.

`FastTyping` печатает весь текст по символам. `FactionTyping` выбирает печать для команды из редактируемого списка, иначе использует вставку. Сопоставление проверяет первый токен целиком и не зависит от регистра: `/cuff` подходит, `/cuffing` — нет. Начальный список включает `/frac`, `/cuff`, `/deject`, `/mdc`, `/chase` и связанные команды; разделители — пробелы, `;` и запятые. Список сохраняется текстовым INI-кодеком. Интервал между символами ограничен 1–100 мс, начальное значение — 5 мс.

Печатный транспорт использует физические VK/scancode вместо `{Text}` и Unicode-пакетов, которые игровой ввод мог игнорировать или превращать в посторонние символы. CP1251 переводится в код символа для RU/US; учитываются Shift и CapsLock, удерживаемые модификаторы бинда отпускаются. Вся строка проверяется до открытия/очистки чата: неподдерживаемый символ вызывает отказ с его кодом. Clipboard не меняется. Проверяются активное окно, состояние чата и поколение отмены во время печати. Потеря фокуса или отмена прекращает отправку; результат после начала ввода считается неопределённым и не вызывает автоматического повтора строки. Владение физическим вводом исключает одновременную вставку, перехват ID и ввод пунктов меню; редактирующие бинды не перемещают курсор во время печати.

В режиме «Печать всего» RP до и после действия вводится без настроенного межсимвольного интервала. Это относится к строкам RP-пакета, а также `/me`, `/do`, `/todo` в RP-последовательностях. Основная команда сохраняет выбранную скорость; `SequenceLineDelay` остаётся отдельной паузой между сообщениями. Режим «Печать фракции» сохраняет вставку остальных сообщений. Редактируемые шаблоны и шаги TYPE используют выбранный транспорт без автоматического Enter. Остановка пользовательской функции отменяет незавершённый ввод и зависимые шаги; проверка контекста выполняется также перед вставкой после `ClipWait`.

Ручной режим **«Перехват цифр»** выбран по умолчанию. Существующий бинд «Ввести ID вручную» (Alt+1 по умолчанию) запускает трёхсекундный перехват цифр верхнего ряда и цифровой клавиатуры. Срок считается от запуска и не продлевается вводом; длительность можно настроить. Повтор бинда или Enter применяет ID досрочно, Backspace стирает последнюю цифру, Esc отменяет. Пустой ввод не заменяет цель; строка сохраняет ведущие нули и допускает до 20 цифр.

Длинный ID полностью помещается в плашке благодаря уменьшению шрифта после 16 цифр. Плашка ID создаётся без активации, пропускает клики и получает исключение из захвата до показа при включённом общем переключателе OBS. Во время перехвата Auto ID приостанавливается. Смена фокуса, профиля или поколения отмены отменяет ввод; открытие чата прекращает сбор цифр. Инжектированные клавиши и сочетания с модификаторами не добавляются в ID. Снятие keyboard hook и удаление плашки выполняются при подтверждении, отмене и выходе. Режим «Через чат» сохранён.

Для ручной установки вместе с основным файлом обязательны `UDF.ahk`, `common.ahk`, `runtime_support.ahk`, `chat_typing.ahk`, `id_capture.ahk` и подключаемые файлы `tests/audit_regression.ahk`, `tests/chat_typing_regression.ahk`, `tests/id_capture_regression.ahk`. Распаковывайте весь архив, сохраняя пользовательские INI-файлы. Исходники AHK остаются CP1251 без BOM с CRLF.

## Память

Из индекса удалены шесть неиспользуемых полей с копиями текста и объединённых наборов токенов. Словарь обходит исходные наборы заголовка и текста без повторного подсчёта. Закрытие LAW сбрасывает навигацию без чтения всех 20 документов; превью хранит не более 500 строк/131072 символов и обрезается одним проходом; закрытие настроек сохраняет значения и уничтожает окно с его контролами.

В двух изолированных запусках U64/Wine working set после индексации снизился с 268,5–268,6 МБ до 228,5 МБ, примерно на 15%. Индекс содержит те же 3544 записи; словарь из 8659 слов и результаты шести запросов совпали с исходной версией. Это замер working set в Wine, не оценка private RAM Windows ANSI x86. Подробные результаты сохранены в `VALIDATION_CLOUD.txt`.

## Проверки и оставшиеся ограничения

В Linux установлены проверенный официальный AutoHotkey 1.1.37.02 и Wine в отдельном каталоге `/workspace/.ahk-cloud`, без замены системных пакетов. Проверка загрузки исходников `/iLib` прошла на Unicode x64. Поведенческие проверки выполнялись в отдельной копии с отключённым **только в этой копии** ограничением архитектуры. Поставляемый основной файл сохраняет требование ANSI x86. Дополнительные регрессии проверяют режимы и список команд, ограничения скорости, таймер и редактирование ID, правила подавления клавиш, отказ транспорта во время перехвата и отсутствие изменений Clipboard в Mock. Отдельные нативные проверки под U64/Wine используют реальные клавиатурные события, hook, Edit-контролы и переключение фокуса; это не доказывает работу игрового ввода под Windows ANSI x86. Последний общий запуск: **242 проверки, 0 ошибок, 3 пропущенные группы**: RU/US mapping в Wine и две группы целевой Windows/игровой интеграции. Дополнительно текущий физический транспорт прошёл 36 проверок ASCII, включая все 95 печатаемых символов, Shift/CapsLock, отмену/потерю фокуса, неизменность Clipboard и нулевой интервал RP. Fixture заменяет только загрузчик раскладок: Wine 10 игнорирует HKL в `VkKeyScanEx` и не поддерживает кириллицу через этот API. Русский ввод в новой реализации требует проверки Windows; старый результат `{Text}` не считается доказательством её работы. Отдельно пройдены 25 проверок перехвата ID, 26 проверок настоящего `ReadProcessMemory` на выделенной fixture-памяти и 30 проверок Auto ID с настоящими таймерами и заменёнными внешними игровыми предикатами. Игровые адреса в GTA эти проверки не подтверждают.

**Windows ANSI x86, игровые адреса и ABI, стресс удалённых потоков, реальные DPI/GUI, capture OBS и созданные файлы скриншотов здесь не проверены.** Нативный A32 не запускается в доступной Linux-среде; дополнительная попытка с проверенным пакетом QEMU запустила 32-битный Wine, но не загрузила официальный A32 executable. Полный GUI исходной и изменённой версии под U64/Wine аварийно завершался при создании многострочных полей; эти запуски не считаются успешной проверкой полного интерфейса. Отдельный preview первых трёх страниц без страниц 4–13 проверен инспектором `tools/audit_gui.ahk` в том же процессе: профиль 51 контрол, чат 68 контролов, интерфейс 68 контролов; на каждой странице 0 ошибок пересечения/метрик и 0 предупреждений при 96 DPI. Графитовая палитра дополнительно проверена снимком окна после отключения системной темы фоновых Progress-панелей. После уменьшения клиентской области до 1163×583 проверена прокрутка страницы интерфейса и переключение разделов: 33 видимых контрола, 0 ошибок и 0 предупреждений. Новая нижняя карточка печати и ID на странице чата проверена после прокрутки: 60 видимых контролов, 1860 проверок, 0 ошибок и 0 предупреждений. Эти результаты ограничены выбранными страницами, средой Wine и текущим DPI. Дополнительно 92 проверки открытия/закрытия настроек подтвердили сохранение значений при перестроении и удаление всех 285 дочерних HWND после каждого закрытия в шести циклах. Сохранение INI в этом GUI fixture отключено режимом preview и проверяется отдельной логикой.

Без проверенного эталона `azmp.dll` запись в игру и удалённые вызовы отклоняются. Чтение Auto ID/чата проверяет структуру и цепочки указателей, но эти проверки не доказывают совместимость каждого игрового билда. Один лишь вычисленный хеш не подтверждает правильность смещений/ABI: нужен соответствующий проверенный билд. Если состояние чата невозможно безопасно прочитать, клавиатурная отправка также отказывается продолжать. При выходе с ещё исполняющимся удалённым потоком его рабочая память намеренно не освобождается; единственная такая область остаётся до завершения целевого процесса.

Для проверки в Windows запустите `tests\run_windows.cmd "C:\путь\AutoHotkeyA32.exe"`. Отчёт создаётся как `audit_selftest_report.txt`; код выхода ненулевой при провале. Затем вручную проверьте настройки и переключение страниц при 100/125/150% DPI, смену профиля/StopAll во время сценария, реальный захват OBS при включении/выключении настройки и действия на проверенном билде игры. Для новых режимов проверьте русские сообщения и служебные команды в игровом чате на выбранной скорости, отмену во время печати, Alt+1 → цифры → повтор Alt+1 и подтверждение по истечении трёх секунд; плашка должна сохранять игровой фокус и скрываться вместе с другими окнами при включённом OBS-переключателе.

Старые проверки карт требуют необязательных изображений из `assets/law_maps`: в исходном репозитории их нет. Этот патч не создаёт поддельные карты и не объявляет такие проверки пройденными.

Для проверки пересечений откройте нужную страницу настроек и запустите `tools\audit_gui.ahk` через AHK v1. Отчёт `GUIaudit_report.txt` содержит реальные координаты контролов, обнаруженные пересечения и доступные метрики шрифтов. Повторите для профиля, интерфейса и длинных страниц при 100/125/150% DPI. Отчёт является снимком одной видимой страницы.
