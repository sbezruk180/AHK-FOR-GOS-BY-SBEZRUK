# Доработка проекта

Сначала прочитайте [архитектуру](docs/desktop/ARCHITECTURE_RU.md) и [инструкцию сборки](docs/desktop/BUILD_AND_RUN_RU.md). Пользовательский продукт — один ANSI x86 EXE. Исходный режим AHK сохраняется для разработки.

- AHK-код: CP1251 без BOM, CRLF; официальный runtime 1.1.37.02 ANSI x86. Сохраняйте ограничения game ABI.
- `helper.ahk` — канонический модуль, не генерируется из main и не дублируется. Проверка: `python tools/sync_helper.py --check`.
- Разметку/контролы размещайте в UI-модулях, сценарии — actions/automation; не добавляйте игровую отправку в рендер окна. Сохраняйте центральные тему и Capture_BeforeShow.
- Не обходите очередь, поколения отмены, фокус/чат/ID-guards и владение HANDLE/удалёнными потоками. Не повторяйте неопределённый результат отправки.
- Сохраняйте INI/неизвестные ключи. Добавление полей должно проходить read/write/normalization/migration, а не только UI.
- Выполняйте `python tools/check_migration.py` для сохранения старых функций. При намеренном изменении обновляйте текущий отпечаток через `--write`, описывая поведение; отсутствие функции не разрешается обновлением отчёта.
- Сборка: `build.ps1`; артефакт: `tools/verify_exe.py`. Регрессии: `tools/run_desktop_checks.py release/AHK_FOR_GOS.exe` с одноразовыми данными. A32/game/OBS/DPI результаты отделяйте от Wine/U64.
- `AHK_FOR_GOS_TEST_U64.exe` не является игровым продуктом и не должен попасть в `release`.
- Прежде чем публиковать релиз, обновите CHECKSUMS.sha256 для отслеживаемых файлов, проверьте `tools/validate_package.py` и сравните опубликованный EXE с его SHA-256.

Сохраняйте лицензию проекта, notices и исходники используемого runtime. Указывайте изменения относительно версии SBezruk180.
