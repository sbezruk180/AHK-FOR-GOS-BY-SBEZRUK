# Результаты переноса и проверок

Проверка 16 октября 2026. **Релизный файл — `release/AHK_FOR_GOS.exe`, ANSI x86.** Облачные исполняемые проверки выполнялись на явно обозначенной **Unicode x64 тестовой сборке** того же графа исходников под Wine 10/Xvfb. Единственное тестовое изменение при её сборке — снятие ANSI x86 guard; тестовый EXE не входит в release. Дополнительно опубликованный релизный ANSI x86 EXE успешно запущен на нативном Windows runner GitHub Actions.

## Проверяемый результат

- Релиз: PE32 GUI, Intel i386, **4 943 872 байта**. SHA-256: `39fa414bbd565bdc7bb5cf087b808c87facee83f14b1857e62c6c209d07e1067`.
- 38 подключаемых исходных модулей, единственный helper, **84 побайтово проверенных ресурса**. Внутри скрипт, 20 LAW-документов/их отпечатки, исходники диагностики, manifest и лицензии. Не осталось внешних исполняемых include-зависимостей.
- Все **1 284 исходные функции** найдены ровно один раз; тела **1 252 совпадают** с исходными, **32 адаптированы** для данных, ресурсов, диагностики и жизненного цикла. Сохранены 191 именованный обработчик и прежние контекстные hotkey-блоки. `UDF.ahk` и `common.ahk` не изменены.
- Реальная игра, игровой ANSI x86 ABI и кадры OBS **не проверены**. Сохранение кода и корректный PE32 не являются доказательством клиентской совместимости.

Нативный Windows CI фактически завершился успешно: [run 38904779329](https://github.com/sbezruk180/AHK-FOR-GOS-BY-SBEZRUK/actions/runs/38904779329), commit `7ac2bbf1a83b535f5080d736f1aefb857a765435`. ## Исправления, выявленные проверками

- Нативный CI выявил представление false как пустой строки `A_IsUnicode` в ANSI runtime. Машиночитаемый `--runtime-info` теперь явно выдаёт `0`/`1`; это исправление проверено успешным Windows-запуском.
- Обновление отсутствующего списка биндов больше не создаёт лишнее GUI и не обращается к его несуществующим контролам.
- Отмена legacy `Input` корректно обрабатывает отсутствие активного ввода, включая вызов из `try`; остальные ошибки не скрываются.
- Диагностика получает HANDLE через CreateProcess, не заменяет основной экземпляр и показывает отчёт в собственном окне. Убрана зависимость viewer от внешнего редактора.
- Индекс LAW проверяет существование пользовательского файла до FileGetSize: встроенный ресурс не вызывает исключение как отсутствующий файл.
- Старые статические проверки используют настоящие границы функций после модульного переноса. Ссылки тестов приведены к фактической базе (определение сотрудника — ФЗОП 17.1). Тексты законов и алгоритмы поиска не менялись.
- Жёсткое старое число страниц заменено более строгой проверкой сохранения всех не-пробельных символов каждого документа; число страниц зависит от шрифта/DPI.

Отдельно исправлено **тестовое окружение**, а не шрифты продукта: Wine GDI падал в GPOS при использовании закэшированных внешних шрифтов; ошибка воспроизводилась и до переноса. Удалён проблемный кэш/регистрации в собственном Wine-prefix, для теста задан DejaVu fallback. Доступ RPM к собственному fake-процессу зависит от свежего Wine server в этой sandbox; runner явно обновляет только заданный тестовый prefix. Оба ограничения не замаскированы правками игрового backend.
