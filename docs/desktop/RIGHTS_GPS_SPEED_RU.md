# Права и ускорение GPS — 20.10.2026

## Отправка прав

Игровой вызов мог нормально вернуться с произвольным EAX, включая `0xFFFFFFFF`. Этот DWORD попадал в код завершения удалённого потока. Проверка `exitCode < 0xC0000000` ошибочно считала такой обычный возврат сбоем. Первая строка уже могла быть отправлена; результат `-2` отменял остальные строки пакета.

В конце производственного x86-стаба добавлен `xor eax, eax` перед `ret 4`. Нормальный возврат теперь даёт нулевой код потока. Исключение/неопределённое завершение по-прежнему не считается успехом; повтор запуска и вставка после него запрещены.

Очередь также не снимает следующую строку, пока уже существует незавершённая операция памяти. Это ожидание не тратит попытки отправки и не отменяет пакет. Обычный фоновый таймер продолжает опрашивать поток.

Обработчик прав использует прежний пользовательский текст, разбивает его по строкам и сохраняет интервал 1000 мс (или больший пользовательский интервал последовательностей). При подтверждённом отказе появляется собственное уведомление, причина дописывается в лог. Пользовательские `/me` и другие RP-строки сохраняют прежнюю независимость от скорости печати.

## GPS

- Открытие `/gps`: пауза **650 мс** вместо 1000.
- Только у GPS: удержание клавиши **20 мс**, межклавишная пауза **10 мс** вместо 50/30; дополнительная пауза 35 мс после каждой стрелки убрана.
- После выбора пункта: **200 мс** вместо 500.
- Перед последним Enter: **50 мс** вместо 100.

Home, 15/16 стрелок, номер, Enter и отмена/фокус/владение вводом сохраняются. Настройки клавиш восстанавливаются после каждой отправки; другие меню не ускоряются. Проверка диалогов не возвращается. Фиксированные паузы требуют проверки при фактической задержке сервера.

## Проверки

Локальный U64 стенд очереди: **12 / 0 ошибок**; отправка пяти строк, пользовательский текст, пауза при занятой памяти, продолжение и отмена, отсутствие повторов и уведомление. Отправитель памяти в этой группе — считающий приёмник, исполнение x86 явно пропускается.

GPS: **22 / 0 ошибок** с реальными Win32 LISTBOX/EDIT и событиями клавиш. Одинаковый сценарий на одном стенде: **4477 → 1840 мс**, примерно в 2,4 раза быстрее. Исходник до ускорения — commit `c8e01c925e05418b81fc49cb96b042a3e00aa74f`; оба прогона завершились с кодом 0 и 22 успешными проверками. Игровой процесс/транспорт — явные подмены.

В Windows CI успешно выполнен отдельный **ANSI x86** стенд (**13 / 0 ошибок**): производственные очередь/UDF/эмиттер исполняют вызов в собственном процессе на выделенной памяти. Целевая функция учитывает фактические вызовы и нормально возвращает `0xFFFFFFFF`. Версия стаба до исправления воспроизвела `sent=1; state=unknown; calls=1`; исправленная отправила все пять. `ExitThread(0xC0000005)` отдельно проверяет сохранение отказа при ненормальном завершении. Это проверка механизма, не запуск GTA и не подтверждение получения сервером.
