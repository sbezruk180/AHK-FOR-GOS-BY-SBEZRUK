# Меню, скрытие OBS и исходный профиль — 26.10.2026

## Причины и исправления

`Capture_RefreshWindows()` выполняется каждые 300 мс и раньше всегда перезаписывал `CaptureStatusText`. `UpdateAutomationSettingsStatus()` тоже обновлял неизменившиеся строки. Теперь запись выполняется только при отличии текста; повторная роль кнопки также не вызывает invalidate.

Кнопки рисуются в собственных буферах. Постоянная композиция всего окна (`WS_EX_COMPOSITED`) не используется для совместимости с живым переключением display affinity в Windows. Убран лишний layered-режим полностью непрозрачного меню и повторная настройка окон после показа. Перед повторным показом уже оформленного HWND стили не устанавливаются заново. Переходы страниц, ввод и кликабельность сохранены.

Раньше приватный ввод добавлял своё окно в `CapturePrivateWindows`, и условие `OBSHideWindows = "On" || private` не давало выключить скрытие. Теперь решение принимает общий переключатель. При On приватный ввод по-прежнему требует подтверждения защиты Windows; при Off он открывается без исключения из захвата. Выбор в списке применяется сразу и сохраняется, включая уже созданные окна.

## Исходный профиль

`assets/defaults/profiles.default.ini` побайтно совпадает с присланным `profiles_export.ini` (SHA-256 `01a75e01e8e5a2977ad82e3f1404fede896ee5a5675b8e652494e0e9b4a29860`). В нём два профиля, выбран «Основной». Его настройка OBS по умолчанию — On; пользователь может сразу переключить Off.

Первый запуск создаёт INI из этого шаблона. Существующие пользовательские файлы не заменяются; запись через временный файл не допускает перезаписи чужого назначения. Для EXE шаблон встроен как RCDATA, для AHK он находится в assets. В Unicode тестовом хосте INI сохраняется в UTF-16 для корректной работы системных INI API на англоязычном Windows; ANSI x86 копирует исходные CP1251 байты.

В экспортированных сочетаниях найдены `!е` и `+^а`. При загрузке они нормализуются в `!t` / `+^f`, сохраняя физические клавиши и модификаторы. Сам исходный экспорт не изменяется.

## Проверки и границы

Desktop-smoke проверяет первый запуск, оба профиля и активный выбор, декодирование RP, сохранность существующей INI, отрисовку меню, отсутствие лишней инвалидации кнопки, On/Off для созданного приватного окна, десять живых циклов переключения, WDA_NONE и запись режима в INI. Состав EXE и установщика сверяется с исходниками и шаблоном.

Это не проверка настоящего OBS и не проверка GTA/Amazing. Реальный метод захвата и работу меню поверх конкретного полноэкранного клиента необходимо проверить на пользовательском компьютере.

Локальная проверка GUI в Wine: 133 проверки, 0 ошибок. Отдельный audit-selftest: 496 проверок, 0 ошибок, 3 группы интеграции пропущены. Протокол Windows и результаты нативного запуска публикуются в артефактах workflow обновления.
