# Требование остановки: освобождение очереди

В режиме печати каждый символ ошибочно проходил через задержки навигации по меню: `SafeSend(Event)` заменял настройки печати на интервал 30 мс и удержание 50 мс. Пока набиралось длинное требование `/m`, отправитель удерживал очередь и физический ввод. Это создавало паузу, похожую на ожидание окончания 15-секундного таймера.

Исправлено:

- Символы используют отдельный режим `SafeSend(Text)`: тот же физический `SendEvent`, проверки фокуса, поколения отмены и владельца ввода; скорость задаёт `SendChatTyped`, без добавления задержек меню.
- Нажатия GPS и игровых меню сохраняют интервал 30 мс и удержание 50 мс.
- Сообщения `/m` из RP-последовательностей, как `/me`, `/do`, `/todo`, отправляются без настраиваемой паузы между символами. Обычные фракционные команды сохраняют пользовательскую скорость печати.
- 15-секундный отсчёт, звук, две строки требования, порядок очереди и защитные ограничения сохранены. Физическая отправка одного сообщения по-прежнему не смешивается с другой автоматизацией.

Проверка причины выполнена на одном native стенде с функциями до изменения и после него: **20 символов — 1896 мс → 491 мс**, содержимое поля точно совпало с проверяемой строкой. До изменения тест скорости падал, после — прошёл. Удержание клавиши меню после исправления — **52 мс**. Это измерения стенда под Wine, а не скорость конкретного клиента GTA. В Wine доступна только одна раскладка: для проверки цифр подставлен её HKL, смешанный RU/US текст отмечен пропущенным; на Windows стенд проверяет обе настоящие раскладки.

Дополнительно desktop smoke вызывает настоящий `DoStopChase`, проверяет порядок обеих строк требования и следующего сообщения, пустую очередь/освобождённый ввод при ещё видимом активном таймере. Игровой транспорт в этой проверке — явно обозначенный MockMode.

После замены EXE проверь в игре:

1. В режиме «Печать всего» вызови требование остановки. Две строки должны отправиться, отсчёт должен продолжиться.
2. Пока таймер идёт, запусти другой бинд: действие должно выполниться после обычной отправки требования, не ожидая нуля.
3. Повтори со «Вставкой», «Памятью» и фракционной печатью.
4. Проверь GPS на дом: прокрутка и ввод номера должны работать как до этой правки.
5. Проверь пользовательскую скорость обычной печати, отмену автоматизаций и звук в конце отсчёта.

Нативный Windows CI: 88 GUI-проверок и 24 проверки ввода/печати без ошибок, включая смешанную русскую/английскую строку и обе реальные раскладки. Для транспортного теста используется обычное Win32-окно с DefWindowProc; GUI AHK отклонял запрос смены раскладки и давал ложный отказ стенда.

Фактическая работа с Amazing Online и OBS в облаке не подтверждалась.
