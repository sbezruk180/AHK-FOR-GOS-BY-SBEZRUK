# Запуск и сборка Windows-приложения

## Готовый EXE

Запустите `release\AHK_FOR_GOS.exe`. Для запуска не нужны AutoHotkey, Python, .NET, компилятор, папка скриптов и внешняя LAW-база. Обычная работа использует один процесс. Программа содержит официальный runtime 1.1.37.02 ANSI x86 и системные Windows DLL; отдельно устанавливать redistributable не требуется.

Целевая система: Windows 10/11 с поддержкой x86-приложений. Как и исходная ANSI-версия, русский текст предполагает системную кодовую страницу 1251 («Язык программ, не поддерживающих Юникод» — русский; экспериментальный системный UTF-8 этому контракту не соответствует). Скрипт не меняет региональные настройки Windows. Для работы с игрой требуется совместимый Amazing/azmp; сами адреса клиента упаковка не делает универсальными.

Закройте предыдущую копию AHK перед переходом на EXE. Защита экземпляра использует тот же mutex. Для обновления заменяется только EXE; INI и пользовательские файлы остаются.

`install.cmd`/`install.ps1` — необязательная установка EXE и ярлыков в `%LOCALAPPDATA%\Programs\AHK-FOR-GOS-BY-SBEZRUK`. Она не устанавливает AutoHotkey и не меняет ассоциации `.ahk`. Проверяется SHA-256 из релиза. `-NoShortcuts` отключает ярлыки. Удаление сохраняет пользовательские INI и логи.

## Пользовательские данные и прежние настройки

- Если рядом с EXE уже есть `profiles_updated.ini` или `profiles.ini`, программа использует прежнюю папку, если она доступна для записи. Имена профилей, неизвестные INI-ключи, бинды, темы и конструктор сохраняются.
- Для новой установки данные находятся в `%APPDATA%\AHK FOR GOS`.
- Если прежняя папка с INI недоступна для записи, четыре файла конфигурации копируются в папку пользователя **без перезаписи существующих файлов назначения**. Исходные файлы не меняются. При конфликте уже существующих настроек назначения они сохраняются.
- `--portable` или пустой файл `portable.mode` рядом с EXE включает portable-папку. Явный `--portable` завершается с понятной ошибкой при отсутствии прав записи.
- `--data-dir "C:\полный\путь"` задаёт абсолютную папку явно. При переносе можно положить туда свои четыре INI; данные другого каталога автоматически поверх неё не сливаются.
- Перехода на JSON/SQLite нет; используется прежняя INI-схема 14 и прежние миграции/атомарные записи/резервные копии.

LAW встроена. Файл `<папка данных>\laws\TER.txt` переопределяет соответствующий встроенный документ; можно обновлять документы без пересборки. Неисправный пользовательский файл не маскируется встроенной копией. Изображения карт в исходном архиве отсутствовали: их можно добавить в `<папка данных>\assets\law_maps`; в `LIMITATIONS_RU.md` приведена граница проверки. Фон/свои звуки/chatlog остаются пользовательскими данными.

## Автоматическая сборка

На Windows установите **Python 3.10+ только для разработки**, распакуйте все исходники и выполните:

```powershell
.\build.ps1
python tools\verify_exe.py dist\AHK_FOR_GOS.exe
```

Все доступные offline-режимы можно последовательно проверить командой `python tools\run_desktop_checks.py dist\AHK_FOR_GOS.exe`: runner копирует только EXE в отдельную папку и создаёт одноразовые данные.

Результат: `dist\AHK_FOR_GOS.exe`, `dist\AHK_FOR_GOS.sha256`, `dist\AHK_FOR_GOS.build.json`. Запускающему EXE пользователю Python не нужен. Входные AHK-файлы — CP1251 без BOM, CRLF.

Сборка скачивает официальный архив с GitHub по `tools/build/toolchain.lock.json`, проверяет SHA-256 архива и каждого используемого файла, а также соответствующие исходники движка. Кэш — `.build\toolchain`. Указание уже распакованного официального архива:

```powershell
.\build.ps1 -Runtime "C:\tools\AutoHotkey-1.1.37.02"
```

В сборке нет сторонних Python-пакетов. Граф включений разворачивается один раз; повторное включение — ошибка. Объединённый скрипт и ресурсы помещаются в официальную ANSI x86-базу через Windows UpdateResource API. Проверяются архитектура PE32, GUI subsystem и все встроенные байты. Исполняемые файлы не сжимаются упаковщиком и не запускают распаковщик при старте. Установка IDE/Visual Studio для этой сборки не нужна.

`build.ps1` не публикует файлы. Workflow `.github/workflows/windows-exe.yml` собирает и проверяет Windows-артефакт; на hosted runner без CP1251 полные проверки русского ANSI явно пропускаются, а не объявляются успешными.

## Проверки

```powershell
.\release\AHK_FOR_GOS.exe --runtime-info
.\release\AHK_FOR_GOS.exe --audit-selftest
.\release\AHK_FOR_GOS.exe --diagnostics
.\release\AHK_FOR_GOS.exe --selftest
.\release\AHK_FOR_GOS.exe --export-licenses
```

Отчёты сохраняются в папку данных. `--runtime-info` показывает реальную архитектуру/кодовую страницу и встроенные документы; это **не тест игры**. `tests\run_windows.cmd` запускает регрессии EXE с временной папкой данных. Исходный запуск через `run.cmd "C:\tools\AutoHotkeyA32.exe"` также сохранён для разработчиков, но требует всего исходного дерева.

Интеграционная проверка реальных окон и сохранения данных:

```powershell
.\release\AHK_FOR_GOS.exe --desktop-smoke --data-dir "C:\Temp\AHK-GOS-disposable-test"
```

Используйте **только временную папку**, не свои настройки: эта проверка меняет тестовый профиль/бинд/пользовательскую функцию, открывает окна и завершается. Она использует реальный UI/профили/очередь, но MockMode для транспорта; не доказывает отправку команд в GTA. Без явной папки этот режим не запускается.

## Разработка в Linux

Для сборки через Wine нужны официальный U64 build-time интерпретатор, Xvfb/display и существующий корректно подготовленный Wine-prefix:

```sh
DISPLAY=:100 python3 tools/build_exe.py --runtime /path/to/1.1.37.02 --wine /path/to/wine-wrapper
python3 tools/verify_exe.py dist/AHK_FOR_GOS.exe
```

Встроенный продукт остаётся ANSI x86. `--test-u64` создаёт **только тестовый** `AHK_FOR_GOS_TEST_U64.exe`, снимая ABI-guard в тестовой копии. Его нельзя выдавать за игровой релиз или распространять вместо ANSI EXE. Автоматический тест на такой сборке не доказывает работу x86 game ABI. Границы фактически выполненных проверок описаны в `TEST_RESULTS_RU.md`.
