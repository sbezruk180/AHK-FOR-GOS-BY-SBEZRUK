# Палитра, карточки, журнал действий и учебный режим

Изменения сохраняют AutoHotkey v1.1.37.02 ANSI x86, действующие профили INI,
TXT-команды, последовательности и транспорт игры. Смена языка или игровых
адресов памяти для этих функций не требуется. Основной код остаётся CP1251
с CRLF; экспорт карточек — UTF-8.

## Как открыть

В меню «Автоматизация» и в значке приложения возле часов появились кнопки
палитры, карточки происшествия, результата действий, обучения и настройки GPS.
Блочный редактор находится в прежнем конструкторе, кнопка «Блоки».

| Возможность | Использование |
| --- | --- |
| Палитра | Alt+T, либо назначенный ранее бинд личного TXT-ввода. Название, точный `!бинд`, английский алиас или фраза: «зачитать права», «надеть наручники», «сигналы спецоперации». Стрелки выбирают результат, Enter запускает, Tab подставляет название/команду. Пробел подтверждает только распознанный точный `!бинд`; в остальных запросах пробелы остаются частью текста. |
| Карточка | Выберите ID, откройте карточку, введите заметки. Кнопка добавления нормы сохраняет текущий результат поиска законов, кнопка chatlog — подходящие прочитанные строки. Смена цели сохраняет прежнюю карточку и выбирает отдельную. «Новое дело» создаёт новую карточку той же цели. |
| Журнал | «Результат действия» показывает последние 24 операции, завершённые/пропущенные шаги и причину остановки. Повтор доступен только для одного точно неотправленного безопасного сообщения в прежнем контексте. Игровые механические команды, меню и неопределённые вызовы повторять отсюда нельзя. |
| Блоки | Сохраняются исходный текст, комментарии и действующие команды SEND/CHAT, WAIT/SLEEP, TIMER, NOTICE, TYPE и STOP. Доступны перетаскивание, вверх/вниз, добавление, изменение, отключение, удаление, предпросмотр и учебный запуск выбранных блоков. «Применить» переносит изменения в старый текстовый редактор; «Сохранить» записывает сценарий. |
| Обучение | Самостоятельный симулятор чата, предложения ID с F1/F2, меню GPS и условий действий. Можно запустить обычный бинд через палитру или сценарий конструктора. Команды и клавиши остаются внутри приложения. Закрытие отменяет работу и восстанавливает прежние ID и MockMode. |
| GPS | Для каждого профиля задаются отдельно число Down для дома/организации, пауза после `/gps`, пауза открытия поля, пауза перед подтверждением, задержка и удержание клавиши. Предпросмотр показывает ту же последовательность, которая выполняется. Пробный запуск начинается через 3 секунды, только в активной игре; повторов нет. Несохранённые значения можно менять и проверять до сохранения профиля. |

Локальные команды палитры: `!incident` / `!карточка`, `!trace` / `!результат`,
`!builder` / `!конструктор`, `!training` / `!тренировка`, `!gpsconfig`.
Настроенные пользователем TXT-команды имеют приоритет над этими псевдонимами.
Это команды личного окна; дополнительные горячие строки игрового чата для
них автоматически не регистрируются.

## Хранение и ограничения

Карточки лежат в `incidents` внутри папки пользовательских данных приложения;
читаемые выгрузки — в `incidents/exports`. Записи не смешиваются с profiles.ini.
Отдельная карточка ограничена 16 000 символами заметок, 16 снимками норм и
24 строками chatlog. Журнал действий хранит первые 120 шагов каждой операции с общим счётчиком;
в оперативной памяти карточек хранится до 200 записей метаданных;
содержимое карточки загружается при открытии. Файлы старых карточек сохраняются.
Автоматическое ведение карточек начинается после первого открытия журнала
в текущем сеансе; учебные ID и сообщения не записываются в реальные дела.

Совпадение строки chatlog по ID/нику — средство отбора, а не подтверждение
события. Подтверждения от сервера приложение для журнала не выдумывает:
«передано клиенту» означает только результат локального транспорта.

Палитра распознаёт названия и словарь близких фраз; это локальный поиск,
не произвольный языковой интерпретатор. Для незнакомой фразы действие
не придумывается. Предпросмотр не выполняет последовательность.

## Изменённые подсистемы

| Модуль | Ответственность |
| --- | --- |
| `app/command_palette.ahk` | Каталог, поиск, подсказки, выбор, прежний диспетчер действий. |
| `app/incident_card.ahk` | Отдельное хранилище, атомарная запись, заметки, нормы, chatlog и экспорт. |
| `app/action_trace.ahk` | Ограниченный журнал, реальные события очереди/транспорта и проверяемый повтор. |
| `app/gps_calibration.ahk` | Настройки профиля, единый план выполнения/предпросмотра и пробный запуск. |
| `app/training.ahk` | Модель обучения, окна, временный контекст и восстановление состояния. |
| `app/custom_functions.ahk` | Совместимый текстовый сценарий, блочная модель и учебное выполнение. |
| `service_ui.ahk` | Личный ввод с наблюдателем подсказок, сохранением фокуса и прежней политикой OBS. |

## Проверка

Добавлены отдельные проверки каждой новой подсистемы в `tests/*_regression.ahk`;
они подключены к `--audit-selftest` и `--desktop-smoke`. Проверяются реальные
INI/файлы/окна, очистка ввода, независимость карточек, пределы памяти,
отмена, отказ небезопасного повтора, сохранение старых сценариев и изоляция
учебного режима. Фикстуры `tools/build_*_fixture.py` проверяют реальные
Win32-нажатия, InputHook, кириллицу, GPS и транспорт на собственных окнах.
Игровые предикаты и ответы заменяются явно указанными тестовыми границами.

Workflow `workbench.yml` выполняет три повторения для исходного AHK и три
для EXE в Windows ANSI x86, включая исходный и инструментированный код.
На англоязычном Windows runner только тестовые копии получают manifest с
`activeCodePage=ru-RU`; исполняемый код и полезная нагрузка не изменяются.
Публичные файлы обновляются только после успешных шести заданий.

Фактическое взаимодействие с Amazing, сервером, эксклюзивным fullscreen и
видеозахватом OBS требует отдельной проверки на Windows с игровым клиентом.
Успешные проверки в симуляторе и Win32-фикстурах не подменяют эту проверку.
Отсутствие найденных ошибок после этих прогонов не является доказательством,
что ошибок нет во всех возможных конфигурациях Windows и клиента.
