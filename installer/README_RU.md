# Графическая установка AHK FOR GOS

Два самостоятельных нативных приложения Windows 10/11 x64:

- `release/AHK_FOR_GOS_Setup.exe` — установка и обновление.
- `release/AHK_FOR_GOS_Uninstall.exe` — отдельная программа удаления.

Обе программы — C++17 / Win32 / GDI+, с тёмной темой, фиолетовыми акцентами,
плавным наведением и переходами, поддержкой клавиатуры и масштабирования DPI.
Внутри нет CMD, PowerShell, Python, .NET, браузера или скачивания компонентов.

## Установка

Выберите EXE или AHK. EXE запускается самостоятельно. AHK устанавливается вместе
со всеми включёнными модулями, laws и официальным AutoHotkey 1.1.37.02 ANSI x86.
Запуск из ярлыка использует локальный runtime и `/CP1251`; чужие ассоциации `.ahk`
и глобальные установки AutoHotkey сохраняются.

По умолчанию устанавливается для текущего пользователя без администратора:
`%LOCALAPPDATA%\Programs\AHK-FOR-GOS-BY-SBEZRUK`.
Можно выбрать другую отдельную локальную папку. Профили обеих форм общие:
`%APPDATA%\AHK FOR GOS`. Значения профиля заполняет пользователь в приложении;
установщик не угадывает личные данные и не меняет настройки игры/Windows.

Пакет содержит действующий EXE, исходники и все зависимости include-графа,
20 законов, доступные локальные ресурсы, локальный A32 runtime для AHK,
тексты лицензий и соответствующие исходники AutoHotkey. Никаких отдельных
скачиваний при установке нет. Необязательная инструкция доступна слева и
после установки. На главной странице размещён запрошенный пользователем
текст об ответственности за аккаунт и санкции сервера.

Установка проверяет SHA-256 каждого файла до записи. Обновление сначала
готовит файлы в соседней временной папке, затем заменяет установленные файлы;
сбой до фиксации манифеста откатывает замены. Профили не перезаписываются.
Изменённые файлы предыдущей установки сохраняются в папке резервных копий
профиля. Ошибки ярлыков/регистрации показываются как замечания, не скрываются.
Программа регистрируется в списке приложений Windows, доступны ярлыки Пуска
и рабочего стола. Повторный установщик/удаление в той же сессии блокируется.

## Три режима удаления

1. **Все AHK на компьютере.** Поиск на фиксированных локальных дисках: `.ahk`,
   EXE именно AHK FOR GOS и отдельные строки **[ПАПКА ЦЕЛИКОМ]**. Выбранная
   папка удаляется со всеми вложенными файлами, включая файлы других типов.
   Общие папки (рабочий стол, документы, загрузки, профиль, системные корни)
   целиком не предлагаются. Ничего не выбрано заранее. Cloud-placeholder
   OneDrive допускается; junction/symlink и неизвестные reparse-типы пропускаются.
   Удаление доступно после выбора файлов, ввода `УДАЛИТЬ` и отметки о риске
   удаления чужих скриптов. По возможности используется корзина; для
   необратимого удаления Windows запрашивает дополнительное подтверждение.
   Файл, изменившийся после просмотра списка, пропускается с ошибкой.
   Затем удаляются установленный проект и его данные.
2. **Только AHK FOR GOS — полностью.** Файлы установки, собственный локальный
   runtime, ресурсы, профили, настройки, логи и ярлыки этого проекта.
3. **Удалить приложение, оставить профили.** Файлы установки и локальный runtime
   удаляются, настройки/профили/бинды/логи остаются для переустановки.
   Если рядом остаются переносимые INI или посторонние файлы, небольшой
   `install.manifest` сохраняет связь с прежней установкой для переустановки.
   Если всё содержимое приложения удалено, удаляется и пустая папка установки.
   Профили из `%APPDATA%` при этом остаются. Полный режим удаляет и манифест.

В режимах 2/3 чужие EXE и глобальные установки AutoHotkey не удаляются.
Ассоциации других AHK не изменяются. В режиме 1 явно выбранная папка
удаляется целиком, включая расположенные внутри чужие EXE и другие файлы.
Дополнительные файлы, не принадлежащие манифесту установки, сохраняются.
Старый проект без манифеста распознаётся по данным EXE, хешу или характерной
структуре основного AHK. Имена EXE/основного AHK могут отличаться. Включён каталог
60 файлов архивной версии `6b1a595`, в том числе архивные CRLF-варианты CMD/PS1.
В этом случае удаляются только проверяемые известные файлы;
изменённые и неизвестные файлы сохраняются. Для других старых версий потребуется
ручной выбор папки/файлов; удаление по одному похожему имени не применяется.
Ярлыки удаляются по целевому пути или AHK-пути в аргументах, независимо от имени.
При отсутствии файлов приложение не сообщает об успешном удалении. В отчёте
показаны точная папка, число удалённых файлов/папок и причины ошибок Windows.

Режимы 2/3 работают с выбранной копией. Для старого ZIP выберите именно папку
с основным AHK. Для всех копий используйте режим 1, проверьте строки папок и
подтвердите выбранные объекты. Не все версии автоматически считаются одной установкой.
Для удаления старой папки целиком запускайте отдельный унинсталлер из другой
папки, например из «Загрузок»: папка с работающим унинсталлером не предлагается
для немедленного перемещения в корзину. Режимы 2/3 завершают самоудаление
установленной программы после закрытия окна.

Не обещается обход прав доступа: заблокированные/недоступные файлы остаются,
операция сообщает об ошибках и даёт подробный локальный отчёт в Temp.
Установленный `Uninstall.exe` удаляется коротким временным нативным помощником
после закрытия окна. На системах без удаления работающего образа небольшой
файл помощника `.tmp` может остаться в Temp для стандартной очистки Windows.
Произвольное содержимое папки приложения не удаляется рекурсивно.

## Сборка

Windows: Python 3.10+ и x64 Visual Studio Build Tools, Developer Command Prompt:

```text
python tools/build_installer.py
```

Linux с MinGW-w64:

```text
python tools/build_installer.py --cxx /path/to/x86_64-w64-mingw32-g++ --windres /path/to/x86_64-w64-mingw32-windres --runtime-archive /path/to/AutoHotkey_1.1.37.02.zip
```

Сборка проверяет официальный архив AHK по зафиксированному хешу и соответствие
исходников действующему релизному EXE. Файлы упакованы в собственный простой
ограниченный контейнер PE-ресурса; пути и SHA-256 проверяются перед извлечением.
`release/installer.build.json` содержит перечень файлов, режимы, хеши исходников
установщика и артефактов. Исходный EXE AHK встраивается побайтово без изменений.

## Проверка и ограничения

`Setup.exe --self-test <путь-к-отчёту>` выполняет реальные установки/обновления/
откаты/удаления в отдельных папках Temp. Чужие диски, настоящие профили,
реестр и рабочий стол не изменяются. На настоящем Windows дополнительно
запускаются обе установленные формы AHK через `--runtime-info`.

`Setup.exe --ui-test <отчёт>` и `Uninstall.exe --ui-test <отчёт>` показывают
настоящие Win32-окна в демонстрационном режиме и проверяют навигацию,
границы контролов, ввод подтверждения и отрисовку. Эти сценарии не устанавливают
и не удаляют пользовательские файлы. Рядом сохраняются BMP-снимки окон.
`--preview` позволяет вручную посмотреть интерфейс без изменения файлов.

Нативный workflow: `.github/workflows/native-installer.yml`. Результаты
публикуются отдельно от кода, статусы и пропуски сохраняются как есть.

Ограничения: поддерживаются Windows 10/11 x64; инсталлер не подписан цифровым
сертификатом. Старое AHK-приложение требует совместимой ANSI-кириллической
среды; на нерусской кодовой странице показано замечание, системная локаль не
переключается. Работа игрового клиента и OBS этим установщиком не проверяется.
